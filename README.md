# PathSnap: map-matching noisy GPS to the road network

UE24CS352A Machine Learning hackathon (PES University). We match each GPS point of a trip to the road arc the
vehicle was on. Round 1 covers preprocessing, labels, candidate generation, features and a 6-model comparison.
HMM/Viterbi, Bayesian HPO, the API and the UI come in Round 2.

**Round 1 result:** XGBoost selected, 0.823 CV Top-1 / 0.860 student_test Top-1 (nearest-arc baseline: 0.51).
Full write-up: [results/ROUND1_SUMMARY.md](results/ROUND1_SUMMARY.md). Rules and specs: [docs/](docs/).

## Setup (Windows, about 10 minutes)

You need **Python 3.12** and **git**. The commands below are for PowerShell.

### 1. Clone

```powershell
git clone https://github.com/NullPointerX-ui/M.L-Hackathon.git
cd M.L-Hackathon
```

### 2. Create the virtual environment and install packages

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell refuses to run `Activate.ps1` ("running scripts is disabled"), run this once and try again:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Your prompt should now start with `(.venv)`. **Activate the venv in every new terminal** before running anything.
The system Python doesn't have these packages.

### 3. Add the dataset (not in git)

`data/` is gitignored because the data is large and comes from the organisers. Copy the provided trip folders
into this layout:

```
data/raw/train/00000001/00000001.track   (+ .nodes, .arcs, .route)   80 trip folders
data/raw/train/00000002/...
data/raw/student_test/00000000/...                                    10 trip folders
```

Check it:

```powershell
(Get-ChildItem data\raw\train -Directory).Count          # 80
(Get-ChildItem data\raw\student_test -Directory).Count   # 10
```

### 4. Check that everything works

```powershell
python -m pytest -q tests        # expect: 2 passed
python scripts\demo.py --no-open # prints the committed Round 1 results (works even before step 3)
```

## Running the pipeline

Run from the repo root with the venv active. Both forms work: `python scripts\<name>.py` and `python -m scripts.<name>`.

| Command | What it does | Time |
|---|---|---|
| `python scripts\run_all.py --skip-train` | Steps 1, 2, 3, 5: rebuild data, labels and features; reuse committed model results | ~1.5 min |
| `python scripts\run_all.py` | Everything, including training all 6 models | ~12 min |
| `python scripts\demo.py` | Print Round 1 numbers, open the map and figures | 10 s |

Individual steps, in order (each depends on the previous one):

| Step | Command | Writes |
|---|---|---|
| 1. Load, project, quality checks, map | `python scripts\preprocess.py` | `results/eda/inventory.csv`, `maps/trip_00000001_raw.html`, `data/processed/points_*.parquet` |
| 2. Per-point labels (monotonic DP) | `python scripts\make_labels.py` | `data/processed/labels_*.parquet`, `results/eda/label_*.{csv,json}` |
| 3. Candidates + features | `python scripts\build_features.py` | `data/processed/*_feats.parquet`, `results/eda/candidates.json` |
| 4. Train + compare models | `python scripts\train_models.py` | `results/model_comparison.csv`, `results/experiments.csv`, `reports/figures/*.png` |
| 5. Summary | `python scripts\write_summary.py` | `results/ROUND1_SUMMARY.md` |

Notes:

- **GPU is optional.** XGBoost tries CUDA and falls back to CPU automatically (the log says which). CPU-only
  training is a bit slower but gives comparable results.
- **Re-running step 4 appends a row set to `results/experiments.csv`** (that file is the experiment log).
  Don't commit a re-run unless you mean to record a new experiment.
- **The map shows as modified after every run.** Folium uses random element IDs, so the file changes even
  though the map is identical. Discard it with `git checkout -- maps\trip_00000001_raw.html`.
- Seeds are fixed (42). With the same data and package versions, steps 1 to 3 reproduce the committed
  results exactly.

## Repo layout

```
src/pathsnap/
  io.py            load a trip (.track/.nodes/.arcs) - never reads .route
  geo.py           per-trip UTM projection, segment geometry, gap segments
  candidates.py    STRtree candidate arcs per GPS point (R = 75 m, top 12)
  features.py      13 features per (point, candidate) - no lon/lat, no trip id, no .route
  labels/align.py  ground truth: monotonic DP alignment of points to the ordered route
scripts/           pipeline steps (above), run_all.py, demo.py
tests/             label alignment + geometry tests on toy data
results/           every number we report (CSV/JSON + ROUND1_SUMMARY.md + training log)
reports/figures/   plots generated by train_models.py
maps/              Folium maps
docs/              hackathon rules converted from pdfs/ - read before changing anything
```

## Team rules (from the assessment policy, see docs/assessment_policy.md)

- Only `pathsnap.labels` (and evaluation code) may read `.route`. Feature and candidate code must never import it.
- Cross-validation is always GroupKFold by `trip_id` on the 80 train trips. `student_test` is for comparison only,
  never for choosing models or hyperparameters. The evaluator set is never touched.
- Every number in the report must come from a script that writes to `results/`. Never type numbers in by hand.
- Don't commit `data/`, secrets or `.env` files.
